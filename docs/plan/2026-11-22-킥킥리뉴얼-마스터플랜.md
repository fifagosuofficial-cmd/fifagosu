## ④ 이름 생성기 상세

### 4-1. 흐름
`introView`(이름 1칸, 최대 6자, 안내 "닉네임도 OK") → `runQuiz`(10문항, 4지선다, 문항 순서 고정·선택지만 섞기) → 결과 계산 → 결과 카드 → 공유.
- 답변 코드: 문항별 **원래 보기 번호(A=0, B=1, C=2, D=3)** 10자리. 예 `2130021130`. 셔플 후 원래 번호는 `qs[i].a.indexOf(선택한 보기)`로 찾음.
- 시드: `rng(hashStr('kk-nick:v1|'+입력이름+'|'+코드))`.
- **배포 후에는 문항 순서·보기 순서·태그를 바꾸지 않는다**(옛 링크 결과가 바뀜). 바꿔야 하면 v2로 올린다.

### 4-2. 이름 처리
| 입력 | N(부를 이름) |
|---|---|
| 한글 3글자 + 첫 글자가 성씨 목록에 있음 | 뒤 2글자 (박도윤 → 도윤) |
| 한글 4글자 + 앞 2글자가 복성(남궁·황보·제갈·선우·독고·사공·서문) | 뒤 2글자 (남궁민수 → 민수) |
| 한글 2글자, 1글자, 그 밖의 4글자 이상 | 그대로 (윤재, 김산) |
| 한글이 아닌 이름(영문 등) | 그대로, **합성형 건너뛰고 상황형** |

- 성씨 목록: 김 이 박 최 정 강 조 윤 장 임 한 오 서 신 권 황 안 송 류 유 전 홍 고 문 양 손 배 백 허 남 심 노 하 곽 성 차 주 우 구 민 진 나 지 엄 채 원 천 방 공 현 함 변 염 여 추 도 소 석 선 설 마 길 연 위 표 명 기 반 왕 금 옥 육 인 맹 제 모 탁 국 어 은 편 용 예 봉 경 사 부
- `L` = N의 끝 글자. 입력에서 `|`, `<`, `>`, 따옴표는 제거.
- 결과 화면(카드 밖 HTML)에 작게 "'{N}'(으)로 불렀어요" 표시. 조사는 기존 `hasJong`/`J()` 사용.

### 4-5. 별명 계산 순서

```
1. 태그 집계 → T1(1위), T2(2위)
   동점 처리: ① 동점 태그 중 T1과 모순 쌍(4-8)이 되는 조합이 있으면 그 조합 우선
             ② 그래도 동점이면 시드 랜덤
2. 합성형 시도: L이 합성 사전(4-6)에 있고 N이 한글이면
   - 그 글자의 단어가 2개면: T1과 태그가 맞는 단어 > T2와 맞는 단어 > 시드로 1개
   - 합성어 = N + 단어에서 첫 글자를 뺀 나머지 (윤재 + 재투입 → 윤재투입, 수빈 + 빈 공간 침투 → 수빈 공간 침투)
   - 별명 =
       (단어 태그가 T1/T2와 맞음) → 그 단어의 "맞춤 별명 틀"
       (안 맞음)                → [T1 합성용 수식어(4-7-1)] + " " + 합성어
3. 합성 실패(사전에 없는 글자, 영문 이름) → 상황형: T1 상황형 풀(4-7-2)에서 시드로 1개
4. 부제(한 줄) 우선순위: ① T1·T2가 모순 쌍 → 반전 문구(4-8)
                        ② 합성형이고 단어 태그가 맞음 → 그 단어의 "근거 문장 틀"
                        ③ 그 외 → T1 태그 한 줄(4-7-3), 상황형이면 T2 태그 한 줄
5. 근거 한 줄(필수):
   합성형: "'{L}' → {단어} · {T1 근거 조각} + {T2 근거 조각}"
   상황형: "{T1 근거 조각} + {T2 근거 조각}"
   T1·T2 근거 조각은 사용자가 그 태그로 고른 보기 중 시드로 1개
6. 칩 3개: T1 보기 칩 1 + T2 보기 칩 1 + 나머지 보기 칩 중 시드로 1 (중복 제거)
7. 등번호: T1 기준 (4-3 표)
8. 길이 검사: 별명 16자(공백 포함) 초과 시
   → 수식어를 다른 것(짧은 순)으로 바꿔 보고, 그래도 넘으면 합성어만 별명으로 쓰고 수식어는 부제 앞에 붙임
```

- **금지(코드로 막기)**: 이름 뒤에 외국어풍 접미사를 붙이는 규칙은 만들지 않는다. 별명은 반드시 N을 포함한다.
- **별명 바꾸기**(있으면 좋음): 후보 = ①위 결과 ②T2를 T1으로 바꿔 계산한 결과 ③합성형↔상황형 반대 방식. 같은 것 제외하고 순환. 결과 링크에는 지금 보이는 별명의 순번 `k`(0~2)도 넣는다.

## ⑥ 공유 장치 · 결과 링크 · Function 명세

### 6-1. 결과 화면 버튼 (카드 이미지 바로 아래, 이 순서)
1. **이미지 저장** — 현행 `saveCanvas`(Web Share 파일 → 실패 시 다운로드). 카톡·인스타 인앱 브라우저(UA에 `KAKAOTALK`, `Instagram`)면 "이미지를 길게 눌러 저장하세요" 안내 표시.
2. **결과 링크 복사** — `navigator.clipboard.writeText(url)` → 토스트 "복사됐어요! 카톡방에 붙여넣어 보세요". 실패하면 링크가 선택된 입력창을 띄우고 "길게 눌러 복사하세요".
3. **링크로 공유** — `navigator.share({title, text, url})`, 미지원·실패 시 2번 동작.
- 버튼 아래 작은 회색 글씨: **"링크에 이름이 들어가요"** (이름이 들어가는 name·duo에만).
- 그 아래 "다른 테스트도 해보기"(hidden 콘텐츠 제외) → 그 아래 광고 자리.

공유 문구:
| 앱 | text |
|---|---|
| name | 내 축구 별명 '{별명}' 나옴 ㅋㅋ 너는 뭐 나와? |
| duo | {A}랑 {B} 투톱 궁합 {라벨} ㅋㅋ 너도 해봐 |
| 유형형 | 나는 '{유형명}' 나옴. 너는? |

### 6-2. 결과 링크 형식
`https://fifagosu.pages.dev/fun/r/?d=<base64url>`
- `d` = base64url( UTF-8 문자열, 필드 구분 `|` ). 패딩 `=` 제거, `+`→`-`, `/`→`_`.

| 종류 | 필드 | 예(디코딩 상태) | 친구가 열면 |
|---|---|---|---|
| name | `v1\|name\|입력이름\|답변코드\|k\|별명` | `v1\|name\|윤재\|1023012230\|0\|후반 12분 윤재투입` | 입력이름+답변코드+k로 **다시 계산**해서 카드 표시 (별명 필드는 무시, og 전용) |
| duo | `v1\|duo\|A\|B\|라벨` | `v1\|duo\|윤재\|민수\|87% 눈빛 패스` | A·B로 다시 계산 |
| 유형형 | `v1\|앱id\|결과키\|유형명` | `v1\|manager\|bus\|버스 2대 주차형` | 결과키로 카드 표시 (결과키 = 결과 객체 id, 없으면 배열 인덱스) |
| go | `v1\|go\|앱id\|라벨` | `v1\|go\|ifplayer\|두 개의 심장 박지성 87%` | 카드 대신 "친구 결과: {라벨}" 배너 + 해당 앱 시작 화면 |

- 앱 허용 목록: name, duo, manager, fan, club, go(ifplayer, balance, blur, price).
- 검증(클라이언트·Function 공통): v=`v1`, 이름 1~6자, 답변코드 10자리 각 0~3, k 0~2, 별명 24자·라벨 30자 이하, 허용 문자 = 한글·영문·숫자·공백·`. , ! ? % ( ) ' · × - ~ #`. 허용 안 되는 문자는 제거. 하나라도 형식 오류면 클라이언트는 허브로, Function은 기본 메타.
- `v`가 다르면(미래 v2 링크를 옛 코드가 받는 경우 포함): 별명/라벨 텍스트만 보여주고 "나도 해보기".

### 6-3. 클라이언트 라우팅
- `route()` 우선순위: ① `location.search`에 `d` → 결과 보기 ② 해시(`{number:'name'}` 별칭 포함) ③ 허브.
- 결과 보기 화면 버튼: **"나도 해보기"** → `location.href='/fun/#/{앱}'` (쿼리 제거 필수), duo는 추가로 **"나랑 {A} 궁합 보기"** → `/fun/#/duo` 에 A 미리 채움.
- 같은 화면에서 공유 시 링크는 친구 것 그대로 다시 쓰지 말고, 사용자가 직접 한 결과만 링크로 만듦.

### 6-4. Pages Function
- 파일: `functions/fun/r/[[path]].js` (`/fun/r/`와 하위 경로 담당. `functions/api/`와 별도, `_routes.json` 불필요)
- 동작:
  1. `url.searchParams.get('d')` → `parseD(d)`(디코딩+검증, 순수 함수로 `export`) → 메타 객체 또는 `null`
  2. `env.ASSETS.fetch(new URL('/fun/', request.url))`로 정적 `fun/index.html` 받기
  3. `HTMLRewriter`:
     - `head` 맨 앞에 `<base href="/fun/">` (항상, 메타 실패 시에도)
     - 메타 있으면 `meta[property="og:title"]`, `meta[property="og:description"]`, `meta[name="twitter:title"]`, `meta[name="twitter:description"]`의 `content`, `meta[property="og:url"]`=요청 URL 전체, `<title>` 텍스트 교체
  4. 응답 헤더 `Cache-Control: public, max-age=3600`, `Content-Type: text/html; charset=utf-8`
  5. 예외는 전부 잡아서 기본 HTML(+base) 반환. 절대 500을 내지 않음.
- og 문구:
| 종류 | og:title | og:description |
|---|---|---|
| name | {N}의 축구 별명은 '{별명}' | 질문 10개 답하면 너다운 별명이 나와요. 너는 뭐 나와? |
| duo | {A} × {B} 투톱 궁합 {라벨} | 친구 이름 넣고 10초 만에 궁합 보기 |
| 유형형 | 나는 '{유형명}' — {앱 제목} | 1분이면 너도 나와요. 해볼래? |
| go | '{라벨}' — {앱 제목} | 킥킥에서 너도 해봐 |
  - {N}은 Function에서도 4-2 규칙으로 성을 뗀다(같은 규칙을 Function에 작은 함수로 복제, 20줄 이내).
- 대비책: `fun/r/index.html` 정적 파일도 둔다(`location.replace('/fun/'+location.search+location.hash)`만). Function이 있으면 Function이 먼저 실행돼요.
- **로컬 모의 테스트(필수)**: `tools/build-fun/test-fn.mjs`에서 `parseD`를 import해 아래 10개 케이스를 `node`로 통과시키기.
  정상 name / 정상 duo / 정상 유형형 / 정상 go / 깨진 base64 / v2 / 허용 안 된 앱 / 이름 7자 / `<script>` 포함 별명(문자 제거 확인) / 답변코드 9자리.
  HTMLRewriter 부분은 가능하면 `npx wrangler pages dev`로 확인, 환경상 안 되면 코드 리뷰로 대체하고 **배포 직후 비서실장이 실제 URL로 확인**(⑧-7).

## ⑦ 기존 콘텐츠 수정 지시

### 7-1. duo (필수)
- 삭제: "제라드-램파드급 (같이 두면 애매)" 및 같은 형식의 2000년대 선수 콤비 비유 전부(QA가 선수 이름 검색으로 확인).
- TIER별로 아래 2개씩 추가(케미명 / 한줄평):

| TIER(%) | 케미명 | 한줄평 |
|---|---|---|
| 39–54 | 패스 주면 둘 다 안 받는 사이 | 공 앞에서 서로 양보만 90분 |
| 39–54 | 단톡에선 절친, 경기장에선 남남 | 하이파이브 타이밍도 엇갈림 |
| 55–69 | 같은 공 보고 반대로 뛰는 사이 | 그래도 뒤풀이 메뉴는 통함 |
| 55–69 | 하이파이브만 국대급 | 골은 없는데 세리머니는 맞춤 |
| 70–84 | 눈빛 패스 반쯤 통함 | 한 명 늦으면 한 명이 커버 |
| 70–84 | 원터치 반, 잔소리 반 | 싸우면서 이기는 투톱 |
| 85–94 | 말 안 해도 원투 패스 | 둘이 합쳐 단톡 점유율 90% |

| 95–99 | 운명의 투톱 | 상대 수비가 둘을 같이 마크함 |
| 100(같은 이름) | 자기 자신과 원투 패스 | 본인끼리 궁합은 당연히 100% |

- 낮은 점수 한줄평이 2문장 이상이면 첫 문장만 남김.
- 결과 링크(`duo`) 연결 + "나랑 {A} 궁합 보기" 버튼.

### 7-2. ifplayer (필수)
- 문항 20 → **14**: `pickQuestions()`의 `out.length>=18` 조건을 `>=12`로(성향 12 + 포지션 + 주발 = 14).
- 코멘트: 표시 시 `split(/(?<=[.!?])\s/)[0]`로 첫 문장만.
- 별명: 앞말과 선수 짧은이름 사이에 공백("두개의심장알리송" → "두개의심장 알리송"). 앞말 안의 띄어쓰기도 원래 문구대로("두 개의 심장 알리송").
- 있으면 좋음: 짧은이름과 정식이름 표기 불일치(후이 코스타/루이코스타) → 카드의 두 곳 모두 같은 필드 사용.
- 결과 링크: `go` 라벨 = "{별명} {싱크로율}%".

### 7-3. balance (필수 1개, 나머지 있으면 좋음)
- **교체(필수)**: "월드컵 우승 + 대머리" 문항 → **"월드컵 결승골 넣고 평생 그 얘기만 듣기 vs 이름은 아무도 모르는데 리그 우승 10회"**
  - 반응 A: "명절마다 결승골 재방송 상영회." (낭만) / 반응 B: "메달은 서랍 가득, 알아보는 사람은 0명." (실리)
- 교체(있으면 좋음): "축구 게임 만렙 vs 실제 리프팅 100개" 반응 → 만렙: "손가락은 국대, 체력은 튜토리얼." / 리프팅: "공원에서 하면 구경꾼 생김. 단, 10개째부터 숨참."

### 7-4. price (있으면 좋음)
- 금액 표시: 계산값 ×10,000 후 억·조 단위로("38만 원" → "38억", 최고 약 "4,700억").
- 치킨 환산은 바뀐 금액 기준(치킨 1마리 2만 원)으로 다시 계산.
- "오히려 돈 받고 보내야 함 — 상대 팀이 데려가 주면 감사 인사를 드려야 해요." → **"숨은 원석 — 스카우터가 아직 못 찾았을 뿐."**

### 7-5. club (있으면 좋음)
- 쏠림 보정: 점수 = 득표 ÷ 그 구단이 선택지에 등장한 횟수. % 공식은 유지.

## ⑩ 문구 톤 가이드 (보충 문구를 쓸 때 기준)

1. 한 줄이 곧 콘텐츠: 별명 16자, 부제 24자. 설명이 필요한 농담은 버림.
2. "너답다": 사용자가 고른 답의 구체 디테일(7시 12분, 알람 5개, 단톡 120개)을 그대로.
3. 숫자·시간·행동으로: "자주 늦음" X → "후반 12분 입장" O. 칭호형("도움왕", "연속골 세리머니")은 웃음이 없어서 X.
4. 해축러 디테일은 축구 몰라도 대충 아는 수준까지(교체, 연장전, 하이라이트, 유니폼, 새벽 경기, VAR, 오프사이드).
5. 자기비하 대신 귀여운 반전("의욕 100, 체력 15").
6. 유행어는 결과당 최대 1개, 검수된 것만(현재 '딸깍' 정도). 이번 데이터엔 안 씀.
7. 실존 인물은 긍정 톤만. 정치·혐오·외모·성별 고정관념 금지.
