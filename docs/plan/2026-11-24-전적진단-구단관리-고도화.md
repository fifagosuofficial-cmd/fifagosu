### 상대 팀컬러 승률 상세 기준

- 입력: 각 경기의 상대 선발 선수 `spId`, 경기 결과, 기존 일일 수집 선수 상세의 `nationId`, `clubs`, 공식 팀컬러 목록.
- 경기별 판별: 동일 국가 또는 클럽에 해당하는 상대 선발이 3명 이상이면 소속 팀컬러 후보로 인정하고 인원수가 가장 많은 후보를 대표 팀컬러로 선택한다. 동률이면 둘 다 기록하되 한 경기의 전체 표본수는 중복 증가시키지 않는다.
- 특성 팀컬러: 수집된 공식 명단과 선수 ID 일치 근거가 있을 때만 인정한다. 이름 유사도만으로 판정하지 않는다.
- 집계: 팀컬러별 경기수·승·무·패·승률을 계산한다. `승리 TOP 3`은 승률 내림차순, `패배 TOP 3`은 승률 오름차순이며 동률은 경기수 많은 순이다. 표본 1경기는 순위에서 제외하고 `표본 부족`으로 분리한다.
- 표현: 전적진단 요약 아래에 한 화면 6개 이내의 간략 카드로 배치한다. 팀컬러명, `N경기`, 승률, 승무패만 보여주고 `상대 선발 기반 추정` 안내를 붙인다.
- 성능: 브라우저가 경기마다 선수 상세 shard를 대량 요청하지 않도록 `derive.py`가 `spId → 팀컬러 ID` 압축 정적 파일을 일일 생성한다. 같은 구단주 검색 내에서는 계산 결과를 재사용한다.

## ④ 대표가 결정해야 할 것

구현을 막지 않도록 아래 기본안을 적용하되, 대표가 다르게 원하면 변경한다.

1. **팀컬러 판정 범위**: 기본안은 근거가 확실한 국가·클럽 팀컬러와 공식 명단이 있는 특성 팀컬러만 사용한다. 불완전한 이름 추정은 하지 않는다.
2. **성장 기록 저장 위치**: 서버비 0원과 개인정보 최소화를 위해 기본안은 브라우저 로컬 저장이다. 기기 간 동기화·로그인은 이번 범위에서 제외한다.
3. **랭커 비교 공개 기준**: 표본이 부족한 공식경기나 예산 구간은 수치를 만들지 않고 `표본 부족`으로 표시한다.
4. **광고 배치**: 기존 슬롯을 유지하고 신규 고정 광고는 넣지 않는다. 기능 안정화 후 실제 체류·스크롤 자료를 보고 별도 결정한다.
5. **배포 단위**: 대표가 전체 완료 후 한 번 배포를 요청했으므로 기본안은 모든 필수 기능과 QA 완료 뒤 한 번 배포한다. 중간 단계는 로컬 빌드로만 검증한다.
