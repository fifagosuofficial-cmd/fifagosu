## ② 콘텐츠별 억지·재미없는 문구 예시와 평가

### 1. ifplayer (내가 축구선수라면?)
1. 별명 **"두개의심장알리송"**, **"PK전담바르테즈"** — 앞말+선수이름을 띄어쓰기 없이 붙여서 읽기 어렵고, 골키퍼에 '두개의심장'처럼 성향과 포지션이 안 맞는 조합이 자주 나와요.
2. **"택배기사마르셀루"** / 닮은 선수는 "후이 코스타"인데 별명은 **"드리블러루이코스타"** — 표기도 안 맞아요(짧은이름 데이터와 정식이름 불일치).
3. 코멘트 "장갑 낀 바르테즈의 몸에 슈팅 본능이 깨어났습니다. 상대 팀은 골키퍼까지 막아야 하는 지옥을 맛볼 거예요." — 2문장 70자 이상, 카드 박스 5줄. 스토리에서 읽히지 않는 길이예요.
- 평가: 콘셉트(닮은 선수+싱크로율+사진)는 12개 중 가장 공유 가치가 높아요. 다만 **질문 20개가 너무 길고**, 포지션 질문이 결과를 크게 좌우해서 랜덤 8회 중 3회가 골키퍼였어요. 별명이 "형용사+선수명" 한 패턴뿐이라 반복감이 커요.

### 2. name (이름 축구선수 생성기) — 대표님 지적의 핵심
1. "윤재 → **윤재 배부르니**(이탈리아), 풀네임 **윤재 알레한드로 곤살레스 이 늦잠 3세**" — 이름 글자를 전혀 쓰지 않고 고정 어미를 뒤에 붙일 뿐이라 누구 이름이든 똑같이 재미없어요. 풀네임은 의미 없는 조합이에요.
2. "손흥민 → **압둘 라면 흥민**(이집트) — 라면 국물로 체력을 보충하는 중동 특급" / "지훈 홀란드 — 골보다 혼자 있는 시간이 많은" / "니에스타 — 니 어디 있노?" — 철 지난 말장난(압둘라→라면, 홀로, 사투리)이에요.
3. 기사 "[단독] 회사 축구 동호회, '윤재 배부르니' 영입 위해 붕어빵 1년치 제시… 본인은 '일단 점심 먹고 생각해볼게요'" + 응원가 "배부르니~ 오오오~ 오늘도 출근 대신 출전해~" — 45개 템플릿이 거의 다 **퇴근·월요일·늦잠·배고픔·치킨·라면** 6가지 직장인 신세한탄 반복이에요. 카드 한 장에 별명·소개·풀네임·기사·응원가·중계·다른 나라 버전까지 7조각이라 정보 과다예요.
- 평가: 결과가 '내 이름'과 연결되는 지점(이름 글자 활용, 받침, 성씨, 내 답변)이 하나도 없어요. 친구에게 보내도 "그래서?"로 끝나는 구조예요. → ⑤에서 질문 결합 구조로 바꾸는 안을 제시해요.

### 3. duo (투톱 궁합)
1. "48%, 서로의 오프사이드. 서로 '네가 차!' 하다 공 뺏기는 사이. 패스를 주면 받는 사람이 없고, 슛을 하면 같은 편이 맞아요." — 낮은 점수 문구가 길고 뻔해요.
2. "63%, 애매한 사이. **제라드-램파드급 (같이 두면 애매)**" — 아는 사람만 아는 2000년대 밈이에요. 10~20대 타깃엔 안 통해요.
3. 역할 "뒤풀이 장소 정하는 사람 · 계산하는 사람", 사건 "같은 축구화를 신고 와서 헷갈림" — 이름과 무관한 랜덤 조합이고, TIER당 문구가 2~3개라 몇 번 해보면 똑같아요.
- 평가: 궁합 %는 순수 해시(근거 없음). 친구 태그 유도형이라 바이럴 구조는 좋은데, 문구 풀이 작아요(EVT 12개, ROLE 6개).

### 4. balance (밸런스 게임)
1. "축구 게임 만렙 vs 실제 리프팅 100개" → "공원에서 하면 사람들이 모여듭니다." — 반응이 맹숭맹숭해요.
2. "월드컵 우승 + 대머리" → "우승 퍼레이드 때 햇빛 반사 조심." — 대머리 개그는 철 지났고 호불호가 커요.
3. 결과 "밸런스의 신, 낭만 40% 실리 60%" — 20문제를 했는데 결과가 비율 하나라서 보상이 약해요. R/S 배정도 자의적이에요(예: "PK 실축"=낭만, "자책골"=실리).
- 평가: 문제 자체는 고르는 재미가 있어요. '친구와 선택 비교'나 '전체 사용자 선택 비율'이 있어야 공유 동기가 생기는데 서버가 없어서 지금은 불가능해요.

### 5. blur (흐린 사진 퀴즈)
1. "주말 하이라이트 시청자 — 얼굴은 아는데 이름이 혀끝에서 맴돌죠." — 무난하지만 웃기진 않아요.
2. "공은 둥글다는 것만 앎 — 괜찮아요. 축구는 원래 보는 것보다 차는 게 재밌어요." — 위로형 마무리라 김이 빠져요.
3. "월드컵 때만 보는 편 — 4년에 한 번 뜨거워지는 타입." — 평범해요.
- 평가: 문구는 문제 아니고 **게임성 콘텐츠**라 점수 경쟁(친구 도전장)에 맞춰야 해요. 위키미디어 사진을 외부에서 불러와서 느린 회선에선 6초 타임아웃 → "사진을 불러올 수 없어요"로 끝나요.

### 6. nation (국적 퀴즈)
1. "국적은 몰라도 축구는 사랑 — 국경 없는 축구 사랑. 그게 진짜 팬이죠." — 위로형.
2. "인간 FIFA 데이터베이스 — 국적은 물론 고향 동네까지 알 것 같은 사람." — 평범.
3. 허브 문구 "선수 873명"이 하드코딩이에요(실제 사진 있는 선수 수와 다를 수 있음).
- 평가: blur와 거의 같은 구조. 리뉴얼 시 하나로 합쳐도 돼요.

### 7. league (몇 부 리그)
1. "K리그2 에이스 — 팀 승격의 열쇠. 단, 원정 버스에서 멀미함." — 랜덤 4회 중 3회가 이 결과. 점수가 중간에 몰리는 구조(12문항 합계)라 **결과 다양성이 낮아요.**
2. "대학 동아리 MVP — 동아리방 트로피의 절반은 당신 것. 나머지는 족구 트로피." — 그나마 나은 편.
3. "프리미어리그 주전 — 비고: 동네 풋살 출입 금지 검토 중" / "K3리그 성실맨 — 약점: 슈팅 각도" — 강점/약점/비고 칸이 단어만 있어서 밋밋해요.
- 평가: 10단계 등급표 카드는 시각적으로 좋아요. 다만 실제 풋살하는 사람만 공감 가능한 질문이라 타깃이 좁아요.

### 8. price (내 몸값)
1. "윤재의 이적료 **38만 원 = 치킨 18마리 + 떡볶이 3인분**, 등급 동네 FA시장 대어" — 금액이 작아서 웃기지도, 자랑스럽지도 않아요. 최고 등급 "세계 이적료 기록 갱신"도 실제 금액은 약 4,700만 원이라 이름과 안 맞아요.
2. 특약 "출석 시 아이스아메리카노 1잔 지급", "파스 정기 배송" — 무난하지만 반복적이에요(답변별 고정).
3. "오히려 돈 받고 보내야 함 — 상대 팀이 데려가 주면 감사 인사를 드려야 해요." — 자기비하 결과는 공유를 안 해요.
- 평가: 영수증/계약서 카드 디자인은 좋아요. 단위를 "억/천억"으로 과장하거나 실제 선수 이적료와 비교("음바페의 0.0003%")하는 게 더 공유될 거예요.

### 9. manager (감독 유형)
1. "버스 2대 주차형 (무리뉴 스타일)" — 랜덤 4회 중 2회. 무난하지만 축구팬 사이에선 이미 흔한 밈이에요.
2. "데이터 노예형 — '기대득점 2.3이었으니까 사실상 이긴 경기야.'" — 괜찮은 편.
3. "헤어드라이어형 — 장점 역전승 장인, 단점 **물병 예산 초과**" — 퍼거슨 밈 그대로라 새롭지 않아요.
- 평가: 12개 중 문구 완성도가 높은 편. 유지 후보.

### 10. fan (팬 유형)
1. "졌잘싸 평화형 — 상대 팀이 잘해도 박수 치는 축구계의 부처님." — 무난.
2. "하이라이트 3분형 — 90분은 길고 인생은 짧아요." — 무난.
3. 해시태그 "#치킨이 메인, 축구는 배경", "#커피가 주식" — 반복되는 치킨/커피 소재.
- 평가: 찰떡/상극 구조는 친구 태그 유도에 좋아요. 유지 후보.

### 11. club (닮은 구단)
1. "리버풀 (의리와 감성) — 친구를 절대 혼자 걷게 두지 않는 사람. 노래방 가면 떼창을 유도합니다." — 랜덤 4회 중 2회 리버풀. 득표 배분상 lfc가 선택지에 많이 들어가 있어서 쏠려요.
2. "AC 밀란 — 패션은 늘 정장 핏." — 연결이 약해요.
3. "토트넘 — 희망회로 장인", "아스널 — 결말은 다음 시즌에" — 팬들 사이에선 웃기지만 해당 팬은 기분 나쁠 수 있어요(그래도 공유는 잘 되는 유형).
- 평가: 구단 성격 비유는 공유 잘 되는 소재. 결과 쏠림만 보정하면 유지 후보.

### 12. number (등번호)
1. "윤재 → 99번, 자신감 MAX. 이 번호를 고른 순간부터 이미 주인공." — 이름 해시로 뽑는데 문구는 '고른 순간'이라 말이 안 맞아요.
2. "지훈 → 12번, 원래 관중석에 있어야 할 번호." — 이름과 아무 연관 없음.
3. "88번 — 팔팔한 체력", "66번 — 66분의 사나이" — 숫자 말장난 수준이에요.
- 평가: 이름→번호 근거가 전혀 없어서 "왜 이 번호?"가 해소 안 돼요. 이름 생성기와 합쳐서 '선수 등록 카드' 한 장으로 만드는 게 나아요.

### 종합
- **이름만 넣는 생성기 3종(name/number/duo)이 가장 약해요.** 결과가 입력(이름)과 연결되지 않아요.
- **반복 소재**: 치킨·라면·퇴근·늦잠·뒤풀이·물 당번이 거의 모든 콘텐츠에 나와요.
- **길이**: 카드 문구가 1~2문장 이상인 곳이 많아 스토리에서 안 읽혀요. "한 줄 요약 + 큰 제목" 구조가 필요해요.
- **유지 가치**: manager, fan, club, ifplayer(축소 버전)는 골격이 좋아요.

### 4-5. 바이럴 루프: 결과 URL로 친구가 내 결과 보기 (서버비 0원)
**핵심 아이디어: 결과가 이미 시드로 재현 가능하니, 서버에 저장하지 않고 URL에 '재현 정보'만 넣으면 돼요.**

1. **결과 URL 형식** (해시 말고 경로/쿼리 — og 메타 때문에)
   - 이름형: `/fun/r/name?n=윤재&a=3120...` (이름 + 답변 코드)
   - 유형형: `/fun/r/manager/bus` (결과 키만)
   - 궁합: `/fun/r/duo?a=윤재&b=민수`
   - 답변은 각 문항 선택 번호를 한 글자씩 이은 문자열(10문항이면 10글자)로 충분해요.
2. **페이지 동작**: `/fun/r/...`로 들어오면 결과 카드를 바로 보여주고, 큰 버튼 "나도 해보기" / "내 결과랑 비교하기". 친구 궁합은 "나랑 이 친구 궁합 보기"로 이어지게.
3. **Cloudflare Pages Functions로 og 메타 동적 삽입 (무료)**
   - `functions/fun/r/[[path]].js` 추가. 요청 시 정적 `fun/index.html`을 `env.ASSETS.fetch()`로 읽고 `HTMLRewriter`로 `<meta property="og:title">`, `og:description`, `og:image`만 바꿔서 응답.
   - 예: og:title "윤재의 축구선수 별명은 '○○○'" / og:description "나도 이름 넣고 10초 만에 확인하기".
   - 무료 한도: Functions 하루 10만 요청. 지금 `functions/api/`가 같은 한도를 쓰므로(넥슨 API 중계) `/fun/r/*`는 카톡 봇 미리보기 + 클릭 정도라 부담 적어요. 응답에 `cache-control` 걸면 더 절약.
   - `_routes.json`으로 Functions가 `/api/*`와 `/fun/r/*`에만 돌게 제한하는 걸 추천(정적 파일 요청이 한도를 안 먹게).
4. **og:image 만드는 법**
   - (추천, 0원) **콘텐츠별·결과 유형별 정적 이미지 미리 만들기**: 유형형(manager 8종, fan 8종, club 12종 등)은 결과 수가 적으니 1200×630 PNG를 미리 생성해 `fun/og/manager-bus.png`로 배포. 기존 캔버스 코드를 Playwright로 돌려 일괄 생성하는 스크립트(`tools/build-fun/make-og.js`)를 두면 돼요.
   - 이름형(무한 조합)은 이름별 이미지를 미리 못 만들어요 → 콘텐츠 대표 og 이미지 1장 + og:title에 이름/별명 텍스트를 넣는 방식으로 충분해요(카톡은 제목 텍스트가 잘 보여요).
   - 동적 이미지 생성(Workers에서 satori/resvg 등)은 무료 플랜 CPU 10ms 제한에 걸릴 가능성이 높아서 비추천.
   - 허브용 기본 `fun/og/default.png` + `twitter:card=summary_large_image`는 바로 추가해야 해요.
5. **공유 버튼 정리**: ① 스토리용 이미지 저장/공유(지금 것) ② **결과 링크 복사**(결과 URL) ③ Web Share 링크 공유(파일 미지원 기기 대비) ④ (선택) 카카오 SDK 공유 — JS 키는 공개되어도 되는 키라 무료로 가능하지만 도메인 등록 필요.
6. 공유 문구도 결과 URL로 바꾸기: 지금 `share()` 문구 뒤에 항상 `/fun/`이 붙어요.

## ⑤ 이름 생성기 구현안: "이름 + 질문 10개 → 웃긴 별명"

### 흐름
`introView`(이름 입력) → `runQuiz`(질문 10개) → 결과 카드 → 결과 URL.
지금 league/price가 이미 "이름 입력 + runQuiz" 조합을 쓰고 있어서(3124–3126, 3173–3175) **엔진 수정 없이** 같은 패턴으로 만들 수 있어요.

### 데이터 구조 (예시)
```js
// 질문: 각 선택지가 [보기, 별명 조각, 성향 점수]
const QS=[
  q('풋살장에 도착하면 제일 먼저?',[
    ['신발끈 세 번 묶기',{pre:'꼼꼼한',k:{calm:2}}],
    ['일단 슛부터 몇 개',{pre:'난사형',k:{shoot:2}}],
    ['편의점 들러서 음료',{pre:'간식 챙기는',k:{chill:2}}],
    ['단톡방에 "몇 시?"',{pre:'지각 확정',k:{late:2}}]]),
  ...10개
];
```
- 별명 = **[수식어(답변 기반)] + [이름 변형(이름 기반)] + [칭호(최고 성향 기반)]**
  - 예: 윤재 + (슛 난사, 지각) → "지각해도 슛은 쏘는 **윤재날두**", "난사왕 **윤재 데 라 슈팅**"
- 이름 변형은 이름 글자를 실제로 쓰는 규칙으로:
  - 받침 유무(`hasJong`)로 어미 선택: 받침 없으면 `-뉴/-뇨`, 있으면 `-인요` 등 → 자연스러움 확보
  - 마지막 글자 활용: "윤재" → "윤재뉴", "재날두", 성+이름 → "윤 재스타" 등 몇 가지 규칙 중 **최고 성향에 맞는 규칙** 선택(슛 성향 → 날두/홀란 계열, 패스 → 니에스타/크로스 계열, 수비 → 라모스/반다이크 계열)
  - 결과적으로 "같은 이름이라도 답변에 따라 다른 별명"이 나와 친구끼리 비교하는 재미가 생겨요.
- 별명 후보를 2~3개 만들어 "별명 바꾸기" 버튼(ifplayer에 이미 있는 패턴, 2738줄) 재사용.

### 결과 결정 로직
- `rng(hashStr(name+'|'+answers.join('')))`로 시드 → 같은 이름+같은 답 = 같은 별명(결과 URL 재현 가능).
- 성향 합산은 ifplayer의 `effects/profile` 방식을 축소해서 사용(성향 6개 정도면 충분).

### 결과 카드 (요소 줄이기)
1. 큰 별명 1줄 (제일 크게)
2. 한 줄 설명 (30자 이내, 답변 2개를 엮어서: "슛은 난사, 도착은 지각. 그래도 골은 넣는 타입")
3. 근거 칩 3개 ("#지각확정 #난사왕 #간식담당") — 답변에서 나온 것이라 "맞아 나 이래" 공감 포인트
4. (선택) 등번호 — number 콘텐츠 흡수
5. 하단 "친구는 무슨 별명? → URL"
- 기사/응원가/중계/풀네임/다른 나라 버전은 빼요(정보 과다).

### 결과 URL
`/fun/r/name?n=윤재&a=2130021130` → 같은 별명 재현 + og:title "윤재의 풋살 별명: 지각해도 슛은 쏘는 윤재날두".

### 작업량 추정
- 엔진 변경: 거의 없음(runQuiz 재사용, 결과 URL 파서만 `route()`에 추가).
- 문구 작업이 본체: 질문 10개 × 선택지 4개 = 40개 조각 + 이름 변형 규칙 6~8개 + 설명 템플릿. 문구는 시장조사원/대표 검수 후 확정 추천.
