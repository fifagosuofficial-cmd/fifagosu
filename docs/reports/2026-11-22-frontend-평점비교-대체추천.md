# 전적 진단: 챔피언스 평균 평점 비교 + 이름 옆 `!` 대체 추천 — 개발 보고서

- 작성일: 2026-11-22 / 담당: frontend-dev + data-engineer
- 요청(대표): 평점이 포지션별 챔피언스 평균보다 낮은 선수도 `!` 표시. 이름 옆 `!`를 누르면 대체 추천 선수 보여주기(신규 특성, 키·몸무게, 능력치 위주, 가격 차이는 일정 범위 안).
- 배포·업로드는 하지 않았어요(비서실장 담당).

## 1. 바꾼 파일

## 2. A. 챔피언스 평균 평점 (`crawler/rating.py`)

- **왜 이렇게?** 넥슨 `ranker-stats`에는 평점이 없고, 전체 매치 목록(`/fconline/v1/match`)은 우리 키로 403이라 '눈덩이 표본'으로 모아요.
- 흐름: 시드 닉네임(기본 `Lampard8`, `--seed`/`RATING_SEEDS`로 추가) → 최근 경기 10개 상세(`/api/matches` 10개 묶음) → 상대 구단주를 후보에 넣고 **등급 숫자가 가장 작은(높은 등급) 사람부터** 방문 → 낮은 등급에서 시작해도 위로 타고 올라가요. 경기 종류 50·52 각각.
- 집계: 경기 당시 `division ≤ 900`인 쪽의 선수만, `spPosition≠28`, `spRating>0`, 양쪽 `matchEndType==0`, 같은 경기는 1번만.
- 결과: 포지션 묶음(GK / CB / FB / DM / CM / WM / AM / W / ST) 평균·표본수 + 정확한 spPosition별. 묶음 표본이 30개 미만이면 `≤1000`(슈퍼 챌린지 이상)으로 넓히고 `basis`에 표시, 그래도 30개 미만이면 그 묶음은 빼요.
- 예의: 호출 사이 0.4초, 하루 경기 상세 최대 400개(종류별 200개), 429면 기다렸다 재시도. 집계 경기가 20개 미만이거나 실패하면 그 종류는 **이전 파일 값을 그대로** 둬요.
- 출력 예: `{"updated":…, "52":{"groups":{"CB":{"avg":7.02,"n":812,"basis":"≤900"},…},"pos":{"5":{…}},"n":180}, "50":{…}, "src":{"users":…,"matches":…,"calls":…}}`
- 확인: `python crawler/rating.py --dry-run`(모의 중계, 저장 안 함)으로 흐름 확인 → 종류별 27명·200경기·7개 묶음 집계 정상.

## 3. B. 대체 추천 후보 (`derive.step_reco`)

- data/list(시세 13단계·포지션별 OVR) + data/detail(키·몸무게·특성)로 묶음별 파일을 만들어요. 시세가 있는 카드만.
- 항목: `[spid, 이름, 그 묶음 최고 OVR(1강), 시세 13개(코드), 키, 몸무게, 신규 특성 수, 특성 번호 목록, 급여, 데이터센터 사용 경기수]`
  - 시세는 유효숫자 3자리 정수 코드(`지수×1000+가수`, 예: 1억 2,400만 → 6124)로 줄였어요. 특성은 파일 앞쪽 `traits` 표(`[이름, 아이콘, 신규 여부]`)의 번호예요.
- 크기 맞추기: 1강 시세 구간(1/4 자릿수)마다 그룹 OVR 상위 N장만 남기고, N은 이분 탐색으로 **300KB 이하**가 되게 정해요. 싼 카드를 쓰는 사람도 같은 가격대 후보가 남아요.
- 실제 데이터(data 브랜치 list·detail 200샤드 전부, 74,351장)로 돌린 결과: 그룹마다 약 2,340~2,450장, 각 293KB(gzip 약 100KB), 4.4초. 남은 카드의 94% 이상에 키·몸무게·특성 있음. CB는 전체 15,251장 중 2,399장 남음.

## 4. C. 화면 (`app.js`, `main.css`)

1. **평점 `!`**: 진단할 때 `/data/rating.json`을 불러와서(없으면 조용히 생략) 같은 경기 종류·같은 포지션 묶음 평균보다 0.1 이상 낮고 3경기 이상 출전한 선수(GK 포함)는 평점을 빨간 숫자+`!`로 표시해요. 툴팁: "챔피언스 기준 같은 포지션(센터백) 평균 평점 7.02보다 낮아요 (내 6.56)". 기준을 넓힌 묶음은 '슈퍼 챌린지 이상 기준'으로 표시해요.
2. **이름 옆 `!` 버튼**: 평점 낮음 또는 기존 공격·수비 `rkLow`가 있는 선수. `<button>`이라 Tab·Enter로 열 수 있고 `aria-label="대체 추천 보기"`. 툴팁에 낮은 수치 요약(예: "낮은 수치: 평점 6.56 (챔피언스 평균 7.02) · 골·슈팅 (상위 랭커 대비)"). `dPStatsView`(선수별 기록), `dPlayerTable`(감독모드 스쿼드 탭 아래 표) 둘 다, 감독모드·공식경기 모두.
3. **대체 추천 창**: PC는 가운데 작은 창, 390px 모바일은 아래에서 올라오는 시트. Esc·×·바깥 클릭으로 닫히고 닫으면 원래 `!` 버튼으로 포커스가 돌아가요.
   - 가격: 내 카드 **현재 강화 단계 시세**(list price[강화-1], 없으면 1강 시세 × 후보들 강화 배율 중앙값으로 추정) 기준, 후보의 같은 강화 시세가 **0.6~1.6배**인 카드만. 시세를 모르면 OVR ±3.
   - 내 카드 자체는 빼고, 같은 선수 다른 시즌은 2장까지. 내 카드보다 그룹 OVR이 2 이상 낮은 카드는 제외.
   - 점수(내 카드 대비): OVR 차이(둘 다 1강 기준) + 신규 특성 수 차이 + 묶음별 신체 가중치(GK·CB·ST는 키·몸무게 가산, FB·WM·W·AM은 몸무게가 80~82kg를 넘으면 감점) − 더 비싼 만큼 페널티 + 더 싸면 약간 가산 + 사용량(유행) 약간. 점수가 0.5 이상인 카드만 최대 5명.
   - 각 줄: 시즌 배지+이름+신규 특성 아이콘, `OVR 126 +2`, `8강 63억 3,000만 -36%`, `188cm · 78kg`, 이유 칩 최대 3개("OVR +2", "신규 특성 1개", "키 +7cm", "시세 -36%"). 누르면 기존 선수 정보창이 **내 카드와 같은 강화 단계**로 열려요(정보창을 닫으면 추천 창이 그대로 남아 있음).
   - 데이터가 없으면 "추천 데이터를 준비 중이에요…", 내 카드 데이터가 없으면 "시세·능력치 데이터가 아직 없어…", 후보가 없으면 "같은 가격대에서 확실히 나은 후보를 찾지 못했어요…" 안내. 맨 아래 "추천은 피파고수 시세·능력치 기준 참고용이에요" 안내.
4. '피파고수의 한마디'와 표 아래 안내문에 평점 비교·`!` 사용법 한 줄을 붙였어요. 기존 랭커 비교·툴팁·표 넓이는 그대로예요.

## 6. 남은 일·주의

- **rating.py는 실제 네트워크로 돌려보지 못했어요**(이 샌드박스에서 fifagosu.pages.dev가 막혀 있음). 첫 수집 후 Actions 로그의 `[rating]` 줄(구단주 수·경기 수·묶음 수)과 `data/rating.json`을 확인해 주세요. GitHub Actions IP에서 Cloudflare가 막으면 그 단계만 실패하고 나머지는 그대로 진행돼요.
- 공식경기(50)는 시드 `Lampard8`의 등급이 낮으면 챔피언스까지 올라가는 데 표본을 꽤 써요. 챔피언스 닉네임을 GitHub 변수 `RATING_SEEDS`(쉼표 구분)에 몇 개 넣으면 표본이 좋아져요.
- 표본은 하루치(종류별 최대 200경기)라 날마다 평균이 조금씩 흔들릴 수 있어요. 필요하면 다음에 며칠치 이동 평균으로 바꿀 수 있어요.
- 추천 후보는 데이터센터에 나온 주 포지션(최대 3개)만 써요. 그 포지션 목록에 없는 자리에서 쓰는 카드는 후보에서 빠질 수 있어요.
- 일부 시즌(예: ICON TM)은 OVR에 비해 시세가 싸게 잡혀 있어서 OVR이 크게 높은 후보가 나오기도 해요. 수집된 시세를 그대로 쓴 결과예요.
- 감독모드 스쿼드 탭 아래 표(`dPlayerTable`)는 모바일에서 원래도 이름이 여러 줄로 접히고, `!` 버튼도 함께 줄이 바뀔 수 있어요(기능 문제는 없음).
